# 滴析 · 体检报告 AI 解读

体检报告上一堆 ↑↓ 看不懂？把报告的照片或 PDF 丢进页面中央的水滴里，AI 会读完所有指标，查阅相关的医学文献，用大白话写成一份解读报告，并生成一个限时有效的分享链接。

![滴析预览](docs/preview.jpg)

## 能做什么

- **拖进来就开始识别**：照片、PDF 都行，一次多份；丢到页面任意位置都可以
- **主动问你**：根据上传的内容，提出需要确认的问题（数值看不清、体检前的状态、多份报告怎么合并），回答后解读更准
- **一份看得懂的报告**：
  - 健康综合评分（区间）和一句话结论，结论放在最前面
  - 每个体检日期的生理年龄区间和主要影响因素
  - 就医建议：要不要去医院、挂哪个科、多久内去、去之前准备什么
  - 需要关注的指标：每项用大白话讲清楚是怎么回事、该怎么办，带参考范围示意
  - 看医生时可以问的问题，以及问它的目的
  - 对症的营养建议（多吃什么、少吃什么）和康复运动建议（频率、强度、注意事项）
  - 复查计划、和上次体检的对比
  - 文献依据：判断引用的 PubMed 论文（综述、荟萃分析、指南）
- **限时分享**：有效期 3 / 6 / 12 / 24 小时，方便马上分享，或者第二天带去给医生看；可选 6 位提取码；可以保存为 PDF；到期后报告页面、原始文件和识别数据自动删除

## 报告怎么写成

1. **识别**：每个文件一次 Claude 调用，全量提取检验指标（含身高、体重、血压等一般检查）、影像发现和医生总检意见；与健康无关的文件会被排除，看不清或需要背景信息的地方生成问题。
2. **查文献**：根据异常发现让 Claude 写出 PubMed 检索式，服务端直接调用 PubMed（NCBI E-utilities）取回近年的综述、荟萃分析和指南（含摘要）。查不到或网络失败时照常出报告，只是没有文献部分。
3. **生理年龄参考值**：指标齐全时，服务端按 Levine 2018 表型年龄（PhenoAge）公式算出参考值（白蛋白、肌酐、血糖、C 反应蛋白、淋巴细胞百分比、平均红细胞体积、红细胞分布宽度、碱性磷酸酶、白细胞计数和年龄；缺 C 反应蛋白时按常见值代入并放宽区间）。
4. **写报告**：分「总览」「指标」「建议」三部分并行调用 Claude，结构化输出用 zod 校验后合并。要求用普通人能懂的话，每段不超过约 60 字（手机上 3 行）；健康评分按固定的扣分规则给出区间。
5. **核对引用**：模型只能引用第 2 步取回的文献，服务端会剔除列表外的 PMID；报告上显示的标题、期刊、年份取自 PubMed 原始数据，不用模型写的版本。

## 快速开始

需要 Node.js 20 或更高版本，以及一个 [Anthropic API Key](https://console.anthropic.com/)。

```bash
npm install
cp .env.example .env     # 填入 ANTHROPIC_API_KEY
npm run dev              # 前端 http://localhost:5173 ，后端 http://localhost:8787
```

只想看界面、不消耗额度时，用示例模式（不调用 Claude，返回示例数据，首页会多一个「用示例报告试试」）：

```bash
npm run dev:mock
```

生产环境（同一个进程提供 API、报告页和打包后的前端）：

```bash
npm run build
PORT=3000 npm start
```

部署到服务器的完整步骤（进程守护、反向代理、HTTPS、防滥用与费用控制、更新与排错）见 [DEPLOY.md](DEPLOY.md)。

## 环境变量

复制 `.env.example` 为 `.env` 后填写。`.env` 不要提交到仓库。

| 变量 | 说明 |
| --- | --- |
| `ANTHROPIC_API_KEY` | Claude API Key，只在服务端使用，不会下发到浏览器 |
| `CLAUDE_MODEL` | 默认 `claude-opus-5-5` |
| `API_PORT` / `PORT` | 开发时后端端口用 `API_PORT`（默认 8787）；生产环境（`npm start`）用 `PORT` |
| `HOST` | 监听地址；放在反向代理后面时填 `127.0.0.1`，留空则监听所有网卡 |
| `PUBLIC_BASE_URL` | 分享链接使用的域名，例如 `https://report.example.com`；留空则用请求的 Host |
| `DATA_DIR` | 报告与原始文件的存放目录，默认 `./data` |
| `COOKIE_SECRET` | 提取码 Cookie 的签名密钥，生产环境务必设置（`openssl rand -hex 32`）；不设置时每次重启随机生成 |
| `NCBI_API_KEY` | 可选。PubMed 的 API Key；不填也能用，填了查文献更快、限流更宽 |
| `TZ_DISPLAY` | 报告页服务端渲染时间用的时区，默认 `Asia/Shanghai`（页面打开后改为访客本地时间） |
| `CLAUDE_CONCURRENCY` | 全站同时进行的 Claude 调用数，默认 4，超出的排队 |
| `RATE_SESSIONS_PER_HOUR` / `RATE_FILES_PER_HOUR` | 每个 IP 每小时可开始的解读次数 / 上传文件数，默认 10 / 60，`0` 为不限 |
| `MAX_REPORTS_PER_DAY` | 全站每天最多生成的报告数，默认 `0`（不限） |
| `TRUST_PROXY` | 信任哪个反向代理提供的访客 IP，默认 `loopback` |
| `MOCK_AI` | 设为 `1` 时不调用 Claude，返回示例数据 |
| `MOCK_REPORT_FILE` | 仅在 `MOCK_AI=1` 时有效：指向一份保存下来的报告 JSON，示例模式会直接展示它 |

## 项目结构

```
server/
  index.ts     路由：上传与识别、回答问题、写报告、发布链接、报告页、提取码、销毁、限流、定时清理
  claude.ts    Claude 调用（识别、生成检索式、分三部分写报告）与提示词
  pubmed.ts    PubMed 检索与摘要获取（全站统一节流）
  bioage.ts    表型年龄（PhenoAge）参考值
  limits.ts    Claude 调用排队与按 IP 限额
  schemas.ts   识别结果 / 问题 / 报告的数据结构（前后端共用类型）
  store.ts     会话与报告的存储、到期判断、清理
  render.ts    报告 HTML 页、提取码页、已清除页（含打印为 A4 PDF 的样式）
src/
  liquid/      水滴：three.js 全屏着色器（光线步进的元球 + 透镜折射）与物理模拟；
               lens.ts 是粘在鼠标上、浮在页面最上层的那颗水珠
  components/  提问菜单、文件列表、有效期卡片（卡里装着水）、完成页
  App.tsx      流程状态机，以及拖放与鼠标交互
```

技术栈：React 19 + Vite + three.js（前端），Express 5 + Anthropic SDK + zod（后端），TypeScript。

## 水滴交互

- **待机**：水滴悬在中央，表面向四周蒸发出细小水珠；中央有引力，散落的水会被拉回来
- **鼠标**（不用按下）穿过水滴：表面被压出涟漪；慢慢离开时拉出一道水颈，断开后一颗水珠挂在鼠标上，移到文字或按钮上会像透镜一样放大、弯折下面的内容（需要 Chromium 内核浏览器）；快速一甩，水珠飞出去再被吸回
- **拖入文件**：水滴向拖着的文件伸过去；在页面任意位置松手，文件变成水珠飞进水滴，溅起水花
- **识别 / 写报告**：水滴沸腾，气泡越来越多，有问题时冒出一颗水珠挂到问题菜单旁
- **出结果**：水滴爆开，发出四张有效期卡片，开始下雨；雨水在页面底部汇成水面，水位涨到上限后转为小雨；雨点打在水面、卡片和鼠标上都会溅开，鼠标伸进水里会推出波浪
- **选有效期**：每张卡里装着水，有效期越长水越多；点一张抽出来，点外面放回
- **再解读一份**：像黑洞吸积，雨滴从四周被吸回，聚成几颗由小变大的水滴，最后一起冲回中心

手感参数在 `src/liquid/engine.ts` 顶部（引力、阻力、粘连、甩落速度、雨量、水位、波速等）。

## 隐私与数据

- 上传的文件只用于本次解读，会发送给 Anthropic 的 Claude API 做识别和解读；查 PubMed 时只发送英文医学检索词，不含个人信息
- 有效期从生成链接时开始计算；服务端每分钟检查一次，访问链接时也会检查，过期的报告页面和原始文件立即删除
- 未完成的上传会话 6 小时后删除，服务重启时也会丢弃
- 提取码按「报告 + 访客 IP」计次，同一访客连续输错 8 次锁定 10 分钟
- 报告页带 `noindex`、`no-store` 和严格的 CSP，模型输出的文字全部转义
